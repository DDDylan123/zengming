# 访谈 → 纯代码复古卡通短片

这个技能来自《百分之二》（Dylan He，2026）的完整制作过程：把哈佛论坛上 Anthropic 首席经济学家的一场访谈，做成一部 2 分 20 秒的黑白橡皮管卡通。下面每一条规则背后都是一次真实的返工，所以写了原因——遇到新情况时按原因判断，不要机械照搬。

成品是**一个 HTML 文件**：Canvas 按时间 `t` 确定性地画每一帧（可拖动、可逐帧截图），外加 `vo/NN.mp3` 旁白和 `music.mp3` 配乐。起点模板在 `assets/film-template.html`（就是《百分之二》本身），改它比从零写快得多。模板结构见 `references/template-map.md`。

## 流程总览

1. 读懂素材 → 2. 写解读 + 片子概念 → 3. 出人物样张让用户选 → 4. 写旁白 → 5. 搭画面（字卡先行）→ 6. 配音 → 7. 配乐 → 8. 检查 → 9. 发布

每一步做完都给用户看，再往下走。用户的品味决定成败，早给样张比做完再推翻便宜得多。

## 1. 读懂素材，逐条核对事实

- 字幕/原文要从头读完，记下所有数字、原话和"他没说"的地方。
- 片子里写的每一个事实都要能在原文里找到出处。凡是你补充的例子（比如新药、接力赛、实习生），旁白里要标出"比方说"，片尾写明"××等例子为补充，不代表对话者观点"。
- **不替说话人下结论。**原话是"也许是这样，也许不是"，就不要写成"他说他不知道"；原话答得犹豫，就不要写成"回答干脆利落"。这是可信度的底线。
- 查出访谈的**具体日期、场合、原视频链接**（用网页搜索，按标题与字幕文件名比对），片头写一行精简出处（含日期），片尾写完整出处和链接。

## 2. 解读 + 概念：避免做成 PPT

先给用户一段解读：这场对话真正讲的是什么（通常是"一个谜题 + 一个概念"），值得留意的层次。

然后设计片子。**最常见的失败是做成"带动画的汇报"**：每句旁白配一张图表、六章六张互不相干的画、屏幕上全是字。用户会直接说"太无聊了，像 PPT"。要的是：

- **一个世界、一个主角、一条贯穿的视觉隐喻**，镜头在这个世界里移动，而不是翻页。《百分之二》的骨架是"那条 2% 的线就是一条路，主角沿着它走"。
- **每个抽象概念换成一个一眼能懂的动作**：弱环/瓶颈 → 沙漏（上面灌得再满，瓶颈一粒粒漏）；"增强你、替代他" → 两人抬木头，AI 让前面的人长出一双胳膊，后面的人被橡皮擦掉。隐喻要让 AI 在画面里"动手"，观众才看得出 AI 的作用（抢椅子就太间接，用户看不懂）。
- 数字做成画面里的物件（路边里程碑、报纸头条、吊牌），不做标注。
- 结尾的"揭示"要回扣开头（世界原来是一支笔画的，那支笔就是 AI）。
- 指代要在观众记忆里：隔了两分钟再说"这条线"，观众已经忘了是哪条，要直接点名"这条百分之二的路"，画面上也再立一次里程碑。

把概念写成 5 段左右、每段一句"画面 + 意思"，用户看懂了再往下。用户说"没看懂"的段落，换更日常的隐喻，不要加解释。

## 3. 画风与人物：先出样张

- 默认画风：**1930 年代橡皮管卡通的手感，黑白为主，只用一个强调色（橙）标关键数字**。片头片尾也全黑白——彩色 logo 会"出戏"，用户明确拒绝过。
- **人物必须原创，不能和参考片撞。**用户发参考视频时，学的是"语法"（灰阶、片门、线条抖动、万物随节拍呼吸），不是造型。避开参考里的标志性元素：派饼眼、四指白手套、大圆头鞋、礼帽。
- **先做 3–4 种人物样张**（同一场景、只换主角与搭档造型），拼成一张总览图发给用户选，选定再做整片。《百分之二》的四个样张：圆头小人 / 硬币先生 / 铅笔头 / 纸偶，用户选了铅笔头——因为"人是铅笔、AI 是钢笔"本身就是隐喻，还顺带给出了"被橡皮擦掉"这场戏。挑造型时优先找**本身就承载主题**的物件。
- 模板里 `LOOKS` 有 B/C/D 三种造型和 `?sample=1&look=X` 样张模式，可以直接改。

## 4. 旁白

- 约 450 字对应 2–2.5 分钟；给画面留沉默，不逐句"念说明"。
- 老动画配**老新闻片口吻**：开头"各位观众！"，句尾多用感叹号，片尾"各位观众，下回再见！"。
- 给配音用的文本要把数字改成中文读法（2026 → 二零二六，4.1% → 百分之四点一），英文专名保留。把每句写进 `vo-lines.json`（`[{id:"01", t:开始秒, text:字幕原文, tts:配音读法}]`），字幕文本写进模板的 `VO` 数组。

## 5. 画面与字卡

- 字幕要**大**（约 60px，在 1080p 画面里），手机竖屏也能看清；长句按标点折行，最多三行。
- 字体选**字形完整**的。站酷小薇体的"回"字字形是坏的（会填成实心方块），已踩过坑；字卡用思源宋体 900（民国报纸式粗宋）最稳。换任何字体后，截图检查所有字幕字。
- 片头卡：片名 + "a cartoon by 作者" + 一行"受 YYYY 年 M 月 D 日 ××与××的一场对话启发"。片尾卡：完 + "制作 作者名"（不放 logo）+ 日期场合 + 标题 + 主讲 × 主持 + 原视频链接 + 补充例子免责声明。播放器在片尾显示一个可点的"看原访谈"按钮。
- 播放器保留：播放/暂停、拖动、1/1.5/2/3 倍速、字幕开关、全屏、`?t=秒` 跳转。

## 6. 配音（LibTV）

细节和踩坑见 `references/libtv-audio.md`。要点：

- 生成前先跑 `libtv-cost-check` 技能报价；扣分以用户截图的积分明细为准（实测：Seed Audio 2 分/条，Minimax 1 分/条，Eleven V3 配音约 19 分/条，MiniMax 音色设计 33 分，Eleven Music V3 约 350 分/首）。
- 先做 3 条以内的**同句试听**给用户选声音。用户嫌系统男声"太娘"时，靠参数压低没用，换引擎/换演法。
- 老新闻片腔用 **Seed Audio 1.0**（文字描述音色："1930 年代老上海新闻片男播音员，民国腔……"）。
- **整篇一次生成**：把全部台词放进一次请求、每句之间要求停顿一秒。分句生成会每句换一个人（Seed 每次重新"演"一个声音），而且同时交 20 条会被并发限制打回 18 条。
- 回来后用 `scripts/split_vo.py take.mp3 vo-lines.json out/` 按停顿 + 字数动态规划切成 N 句，并逐句做老电视处理（`scripts/old_tv.sh` 是同一条处理链的单文件版，用户认可的就是这版质感）。把输出的 `meta.json` 写进模板的 `VO_META`，时间轴会按真实时长自动伸缩。
- 改任何一句台词，都整篇重录（2 分），不要单句补录——声音会对不上。

## 7. 配乐

- 代码合成的小乐队撑不起片子（用户原话"音乐太差了"）。用 **Eleven Music V3**：能指定时长（选略长于片长），描述里按时间段写结构（片名号角 → 轻快走路 → 越来越急 → 放慢独奏 → 笨重后突然停 → 钢琴渐弱 → 结尾"ta-da"），并写明纯器乐、无人声、1930 年代热爵士、老唱片质感。Mureka 不能控时长，不适合跟画面走。
- 放在 `music.mp3`，模板会撤掉合成乐队、只留拟音（弹簧、滑哨、喇叭、沙子），旁白时自动压低配乐，拖动和倍速时同步。

## 8. 检查

- `FILM=file:///…/index.html node scripts/contact_sheet.mjs out 3 14 30 …` 截每场关键时刻拼成总览，逐张看：人物有没有被裁、字幕是否完整、强调色是否只在数字上。
- 带音频的测试用 `python3 -m http.server` 起本地服务（file:// 下 fetch 不到 mp3），确认 20 段旁白和配乐都加载、无报错。
- 切分无法逐句听写核对，告诉用户最可能出错的分界，请用户听时留意字幕和声音是否对得上。

## 9. 发布与交付

- 用 Artifact 发布：`files` 里带上 `music.mp3` 和 `vo/*.mp3`。同一路径重发保持同一链接。
- 每次改动都提交并推送；给用户的回复先说做了什么、链接、哪里需要用户检查，再说花了多少积分。
- 云端环境常见网络拦截：下载 LibTV 结果要放行 `libtv-res.liblib.art`，上传要放行 `libtv-resource-prod.oss-accelerate.aliyuncs.com`；被拦时让用户在环境设置的"网络访问"里加白名单。

## 模板许可
